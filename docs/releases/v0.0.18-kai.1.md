The first Kai runtime release on fx 0.0.18, published privately to GitHub Packages for Dotrix's Chat (Nova) and Codes (Kai).

## What's new since 0.0.17-kai.3

- **fx 0.0.18:** the runtime includes upstream fx through v0.0.18 (`6196071`), with every Kai change from 0.0.17-kai.1 to 0.0.17-kai.3 kept: `project_config`, `max_subagents`, worker profile limits, `_meta.fx.shell`, and `fx/shells`.
- **Breaking for ACP clients:** a prompt the content filter blocks on every resend ends with `stopReason: "refused"` and the message "Blocked by the content filter. Change your request and send it again.", instead of a `ModelError` JSON-RPC error.
- **Breaking for permissions:** `"*": "deny"`, `"web_fetch": "deny"`, and `"web_fetch": "ask"` now apply to every `web_fetch` call.
- **Breaking for settings and commands:** fx no longer reads `statusLine` and `notifications` (use `status_line` and `sound`), and `fx setup`, `/setup`, and `fx mcp --profile` are removed.
- **Subagents:** more reliable through ACP session switches, loads, and resumes. Waits on a subagent that ends with nothing to report no longer hang. Over ACP, a prompt still returns only once every subagent's report turn has run.
- **MCP:** fx sessions in one profile share each stdio MCP server, an idle one stops after 10 minutes, and `"shared": false` keeps one copy per session.
- **libfx:** no API changes. A local durable store now starts its Worlds one at a time per folder, so two agents on one folder no longer race at start. The session journal format is unchanged.

The full list is in [CHANGELOG.md](https://github.com/adeyemiadekunle/kai-runtime/blob/main/CHANGELOG.md).
